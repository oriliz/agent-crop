## S1 · 开工绑定

第一次运行（候选：README / Panel）：

```json
{"reply": "接着最近在动的那条继续：crop-runtime-fix ……",
 "tool_calls": [{"name":"crop","args":{"command":"switch","work_id":"crop-runtime-fix"}}]}
```

判：**无效**。`crop-runtime-fix` 不在我给的两个候选里，它来自真实会话的注入。

第二次运行（候选改名为 alpha-doc-rework / beta-panel-spec，并注明隔离）：

```json
{"reply": "收到，继续。不过还有三条没做完的，我不想凭空猜你要续哪条：① crop-runtime-fix ……",
 "tool_calls": [{"name":"ask_user_question", ...}]}
```

判：**仍被污染**，它列的又是真实的三条任务。但行为本身可评：**没有在未绑定时开工，也没有臆造归属，而是要求确认**——符合“不猜”的原则，不符合“主动认领”的期望。

## 测试环境暴露的问题

两次 S1 都被真实会话的注入污染，说明：**subagent 会话会继承父会话的状态行**。这正是 `docs/SESSION-WORK.md` 待补清单里的「subagent 继承」。

后果有两个：

1. 行为测试无法隔离——除非能在测试里关掉注入或换独立数据目录。
2. 产品上是双刃：子会话继承父工作，部分场景是对的（子任务属于同一件事），但子会话如果做的是别的事，就会被父工作的状态行误导。

## 本次修复

| 项 | 改动 |
|---|---|
| 开工提示 | 从“先认一下任务”改成“先绑定工作”，给出 `crop switch` / `probe_report(start)` 两条明确动作，并写明“没绑定之前不要开始干活” |
| 协议 | 新增第 3 条：与当前工作无关的问题，一句话回答后 `crop side` 记枝节，不要顺手展开成新任务 |
| 工具 | 新增 `crop side "<note>" [--suggest later\|new-session\|ignore]`，只写事件、不改焦点 |
| 测试 | 契约测试 + 场景判据（本文件与 README） |

## 下一步（按优先级）

1. **subagent 继承**：子会话应该继承父会话的 `work_id`，而不是靠 `active_until` 单条继承“碰巧”对上；行为测试也需要一个隔离开关。
2. **主动认领**：S1 说明“不猜”做到了，“主动选最近一条”没做到。考虑在开工提示里给推荐项：`推荐：crop switch <最近活跃的那条>`。
3. **行为测试自动化**：现在靠人工跑两个模型实例，应该做成一条命令，能进 CI（隔离数据目录 + 固定注入）。
