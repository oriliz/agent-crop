## 任务节奏 · 10 分钟黄线 / 30 分钟红线（所有任务适用）

每个任务开始前按 **fast-loop** skill 执行（细节见该 skill，此处只列强制入口）：

1. **开工三件套**：写代码前先输出 ①决策表（待拍板项一次勾完，禁止逐个问答；拍板结果落盘 `$KIT_IDE_HOME/task-metrics/data/decisions/<date>.md`，已拍板项不重辩、翻案写回文件）②陷阱清单 + 依赖预检（从记忆/skill 检索已知坑并逐条写规避；部署/发布/回归类任务开工先跑预检三问——产物可达/环境存活/上游就绪，答案一律活查询）③时间预算 + 拆分。
2. **预估 >30 分钟必须拆**成可独立验证的子任务，标注并行项：长命令（构建/发包/部署/全量测试）后台跑；独立调研、独立仓改动派并行子代理；串行只留真依赖。
3. **进度播报**：>10 分钟任务每 ~10 分钟一行「已完成 X / 正在 Y / 还差 Z」；限时任务剩 5 分钟必须主动给「能交付什么 / 不能交付什么」清单。禁止静默干等。
4. **超时必复盘，但不许借复盘收工**：任务块超 30 分钟（hook 自动计时并注入告警），先给三行复盘——超时点 / 根因 / 下次怎么拆分并行——然后**在同一轮里立刻继续推进**，复盘不是停工信号。可固化的结论当轮写回 skill 或记忆。只有「可自主动作全部做完 + 剩余项确实需要用户拍板」时才交还，且交接时必须带上已准备的方案或默认值，不能把问题原样丢回。
5. **限时诚实 + 压力时刻**：时间不够就报「能交付什么 / 不能交付什么」+选项，不硬赶；被催「快」时先明示取舍（砍什么保什么），禁止为赶时间碰已声明红线（项目红线以项目层声明为准）。
6. 收尾报时：`python3 $KIT_IDE_HOME/task-metrics/bin/task_retro.py --last 3` 取实际耗时，超预算说原因。

耗时数据由 `$KIT_IDE_HOME/task-metrics/` 下的 hook 自动记录，无需手动打点。
本规则依赖模型执行，计时与告警由 hook 确定性保证；套件本体见 ai-coding-efficiency-kit 仓库。
