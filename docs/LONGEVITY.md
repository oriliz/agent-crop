# 长程任务里，怎么让探针不被冲刷掉

> 问题：探针的规则靠 Agent 的主动行为（记得上报、记得守范围）。
> 但上下文会越来越长、压缩会抹掉中段，模型对早期注入的注意力会衰减。
> 这一页定的是：**靠什么机制保证它一直起作用**。

## 0. 先说清楚为什么不能靠"记得"

- 注入的提醒是普通 `user` 消息，会随历史增长被推到很后面
- 压缩（compaction）会替换一段 surface 事件，注入可能正好落在被遮掉的区间里
- 模型对「很久以前的一句话」的依从性，随距离快速衰减

所以原则是：**不靠记忆，靠机制。把规则放在不会被压缩的地方，把状态放在注意力最高的地方，把兜底放在宿主里。**

## 1. 四层机制

### L1 宪法层：插件自己往系统提示里注册段落（不要求用户改任何文件）

DSH 有 `ctx.systemPrompt.section({ name, order, text })`：插件可以注册提示词段落，
每次组装（每个模型步骤）都会带上，渲染成 system/message 节点——
**文本不变时原地替换，不追加历史，不参与压缩**。

所以协议由插件自己携带：

```js
ctx.systemPrompt.section({
  name: 'crop:protocol',
  order: 900,
  text: [
    'Crop 探针协议：',
    '- 开工前用一句话回显目标，并调用 probe_report(phase="start") 登记。',
    '- 收到 [crop] 提醒时，先说一句人话，再 probe_report 报 卡点/原因/证据。',
    '- 用户表示满意或结束时 probe_report(phase="end")，顺手写三句小结。',
  ].join('\n'),
})
```

装插件 = `dsh plugin add`，**用户不需要改 AGENTS.md**。
`AGENTS.md` 模板只作为没有这个 seam 的宿主（Claude Code / Qoder / Codex）的兜底方案。

特点：永久在上下文头部、不占历史 token、不随距离衰减。

### L2 状态层：每个 turn 首步注入一行（注意力最高处）

- 注入点：`agent/pre-step`，且只在 `step === 1` 或工作状态变化时
- 内容：一行，≤ 80 字，例如
  `[crop] 当前工作：runtime；本回合第 12 分钟；上次上报 25 分钟前`
- 位置：消息列表最末 → 是最新、最显眼的位置

为什么是每 turn 而不是每 step：每 step 注入会稀释注意力、增加 token；turn 首步已经覆盖了「这次要干什么」的决策点。

### L3 抗压缩层：压缩结束后立刻补一条

- 监听 `session/event` 里的 `compaction/end`
- 压缩完成 → 在下一个 pre-step 强制注入一次当前工作状态（不受"每 turn 一条"限制）
- 理由：摘要可能把我们的注入遮掉，必须补回来

### L4 兜底层：缺口检测 + 措辞升级

- 每个 turn 结束检查：本轮是否有 `probe_report`
- 没有 → 下一轮注入一行更硬的提醒（「你上一轮没有登记工作状态」）
- 连续 3 轮没有 → 再升一级；**但不阻塞对话**（探针不是卡口）
- 一直不报 → 降级为纯自动采集（时间数据不丢，只丢语义层）

## 2. 频率与长度预算

| 项 | 预算 |
|---|---|
| 注入条数 | 每 turn 最多 1 条；压缩后额外 1 条 |
| 单条长度 | ≤ 80 字（中文） |
| 每 turn 增量 | 约 30–60 token |

## 3. 怎么验证它没被冲掉

**跟进率**：注入提醒后，下一个 turn 内出现 `probe_report` 的比例。

- 现在有历史数据可参考：旧方案 RULE-005 跟进率 77.8%，RULE-004 是 0/17（反例）
- 目标：L2+L4 上线后跟进率 ≥ 70%，且长会话（> 50 turn）不显著下降
- 下降 = 机制失效的信号，而不是"模型今天状态不好"

## 4. 还要验证的两件事

1. **压缩后注入是否真的丢了**——用 `compaction/end` 前后的事件对比确认
2. **首步注入 vs 每步注入**的跟进率差异——如果每步明显更高，再权衡 token

## 5. 宿主差异

| 宿主 | 常驻规则怎么做 |
|---|---|
| DSH | `ctx.systemPrompt.section()` 注册（推荐，零配置） |
| Claude Code | hooks 注入 + 可选 `AGENTS.md` 模板（无系统提示 seam） |
| Qoder / Codex | 同上，实验性 |

## 6. 不做

- 不阻塞对话、不强制作答前必须先上报（探针是镜子不是闸门）
- 不在系统提示里放动态状态（会让提示每轮变化，反而降低稳定性）
