# 工作模式

这份文档收的是「怎么干活」，不是「干什么」：专门记 review 里反复出现的摩擦，以及对应的改法。
它跟 [CONTRIBUTING](../CONTRIBUTING.md) 的关系是——CONTRIBUTING 管边界与流程，这里管节奏与协作。

## 1. 叙事先行，图后行

画图、做界面之前，先把「谁在什么时候做什么」写成 8–10 行文字，给人过一遍：

```
会话开始 → 注入：创建 / 绑定工作项
每步 → 记工具与失败
一轮结束 → 记停止时点
你发下一句 → 记回复时点 → 感知你的反馈
AI 提问 → 前时点 / 后时点（中间是等人）
超时 → 超时提醒 + 鞭策 → AI 反思与上报
收工 → 人类确认 → 总结与复盘
```

文字改一版 1 分钟；SVG 改一版 10 分钟，还要重新渲染核对。
本仓库的 README 时间线改了十几版，前六版都在用坐标猜语义——那段成本本来可以省掉。

## 2. 有分歧就给变体

「上下要不要对齐」「菱形还是竖线」「超时要不要实心」这类是口味，不是对错。
一次给 2–3 个变体让人挑；不要改一版、问一版、再改一版。

## 3. 推前跑 `scripts/check.sh`

```bash
bash scripts/check.sh
```

Python unittest + Node `node --test` + probe smoke，一条命令全跑；CI 只是第二道闸。
本仓库的 CI 曾两次挂在 node 任务上（缺 `npm ci`、测试桩没有 `ctx.inject`），本地一条命令都能提前看到。

## 4. 一个会话一个交付物

玻璃卡片、面板、dashboard 架构、README 塞在同一个会话里，估时就没法准，复盘也混在一起。
拆成多个会话，各自算账。

## 5. 并行时先开 worktree

仓库可能同时有别的会话在改：

```bash
git worktree add ../agent-crop-<task> -b <task>
```

不要在共享工作树上切分支（踩过：分支被切走，提交落到别人的分支上）。

## 6. PR 按主题拆

文档 PR 只带文档提交，行为改动单独 PR，评审时能只看一个主题。
（踩过：一个「改 README」的 PR 带上了本地 main 的五十多个提交。）

## 7. 估时按「未知数」报，不是按分钟

报「预计 3 轮内出图，第 4 轮还没定就停下来对齐」，比报「12 分钟」有用。
超过预估 2 倍，或同一处返工 ≥2 次：**主动**写一行「流程观察 + 现在改什么」，不等用户问。

## 8. 开发机重启用脚本

macOS 没有 util-linux 的 `setsid`，别手搓 `nohup setsid`——会静默失败。
用 `scripts/dev-restart.sh`：python 双 fork 脱离父进程，等端口真的起来，再打印带 token 的 URL。

```bash
scripts/dev-restart.sh 3082 dev
```

## 9. 复盘沉淀：落点比结论重要

复盘完要收口，别只写一段感想。每条经验固定四件套：

1. **结论**：一句话
2. **落点**：哪个文件的哪一节
3. **验收判据**：怎么算它生效了（最硬：下次同类任务，同类错误没再犯）
4. **复查日期**：到期没验证标“待验”，长期零命中就删

落点选择：规范 → `AGENTS.md`（一行换一行）；方法 → skill；机械 → 工具；事实 → `docs/`；一次性 → 不沉淀（写 `none:<原因>`）。

运行时完整决策树由插件自带的 skill `crop-retro` 提供（`dsh/lib/index.js` 的 `RETRO_SKILL`）；收尾时落点写进 `crop_update(phase="end", sediment=...)`，只记指针不记正文——正文仍在目标层。

## 这套约定怎么传到别的会话

会话之间不共享上下文。agent 能看到的是两样：**会话启动 / 首次碰文件时被注入的内容**，和它主动读的文件。
DSH 的注入包是 `@deepseek-ai/dsh-agent-instructions`：用户全局链（`$DSH_HOME/AGENTS.md`），项目链是从项目根
到 cwd 每一层的 `AGENTS.md`（首次请求注入），子目录 `AGENTS.md` 在第一次 `read`/`write`/`edit` 之后注入（on-touch）。

所以按「这条信息对谁成立」分层放，**别都塞进 AGENTS.md**：

| 信息 | 放在哪 | 为什么 |
|---|---|---|
| 这个仓库怎么跑、哪些是硬门禁 | 仓库根 `AGENTS.md` | 只对 cwd 在本仓库的会话注入，不污染别的工作 |
| 画图、PR 拆分、估时这类方法 | 技能（`$DSH_HOME/skills`），或本文档 + 一行指针 | 跨项目复用、按需加载，不占全局上下文 |
| 所有项目都成立的协作底线 | 用户全局 `$DSH_HOME/AGENTS.md` | 唯一真正全局的注入点，越少越好 |
| 一次性任务上下文 | 会话内 prompt，不落地 | 只对这一次有效 |

反例（这次差点犯的）：把「改 README 先叙事后画图」写进 `~/AgentProjects/AGENTS.md`——那是**工作区级**、
所有会话都会读的文件，为一件只在文档/图形任务里成立的事付全量上下文成本。仓库根 `AGENTS.md` 或技能才是它的位置。

## 自查（每次交付前）

- [ ] 叙事文字过过一遍了？还是直接开始画/改？
- [ ] 有口味分歧的地方，给了 2–3 个变体吗？
- [ ] `bash scripts/check.sh` 绿了吗？
- [ ] 这个 PR 只讲一件事吗？
- [ ] 这次超预估了吗？超了的话，我主动说了「哪里空转、现在怎么改」吗？
