# 为什么做 Agent Crop

> 记录于 2026-11-18。这是项目的第一性目标，后续所有设计取舍以它为准。

## 初心

我写这个项目，是想回答一个问题：

**完成一个任务的时候，我究竟花了多长时间，时间花在了哪里。**

## 起因

我曾在并发 agent 里迷失，也曾在上下文切换里迷失。回头一看，产出竟然还不如我自己手写快。

那段时间的问题不是"AI 不够强"，而是：

- 我不知道时间到底花在了哪——是在等 AI、在返工、在切换上下文，还是在做真正的工作；
- 并发 agent 让"进度"看起来很快，但总产出和时间的关系没人算得清；
- 上下文切换的成本被隐藏在"看起来在同时推进"里。

所以我需要一面镜子，而不是一个记分牌。

## 它要回答什么

1. **一个任务到底花了多久**——不是日历跨度，是真正在推的活跃时间；
2. **时间去了哪**——活跃、等待、返工、上下文切换，各自占多少；
3. **值不值**——同样的活，用 AI 做 vs 自己手写，时间和产出分别是什么样；
4. **哪类任务适合交给 AI**——用数据回答，不靠感觉。

## 它不该变成什么

- 不是打卡工具：不评价"今天干了多久"；
- 不是 KPI 工具：不给 AI 打分、不排行；
- 不是审判工具：它记录事实，判断留给人；
- 不是负担：如果为了记账要多花时间，那就本末倒置。

## 判据

- 如果它让我**更快看清"时间去哪了"**，就是对的；
- 如果它**增加我的负担**，就是错的；
- 如果它把"AI 很忙"当成"产出"，那是它该修的问题。

## 一句话

**Crop 是给 AI 的一根马鞭，也是给我自己的一面镜子：催它交活，也让我看清时间到底花在了哪。**
