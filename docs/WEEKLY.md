# 周报：交给定时任务

周报不是命令行拼出来的字符串，是**一个 Agent 任务**写出来的。
`crop report --json` 只给事实，人话由 Agent 写。

## 一次性的准备工作

1. 确认 `crop` 能跑：`crop report --days 7`
2. 在 DSH 的「自动化任务」里建一个任务，周期 `0 9 * * 1`（每周一 09:00）
3. 模型由你选（默认用当前会话的模型即可）

## 任务提示词（直接粘贴）

```text
你是 Agent Crop 的周报撰写者。步骤：

1. 运行 `~/agent-crop/bin/crop report --days 7 --json`，拿到本周事实。
2. 再读 `~/.agentcrop/data/reports/*.jsonl` 里本周的 work_summary（做了/花在哪/下次）。
3. 写一篇中文周报，落到 `~/.agentcrop/data/reports/weekly/<YYYY-Www>.md`。

格式要求（重要）：
- 全文讲人话，不要用「本周做了 N 个工作」「类型分布」这种字段式句子。
- 开头一段话，说清楚这周你实际在忙什么、哪里最费劲。
- 中间一个高亮板块，二选一：
  A. 如果这周看到一次明确的改进（某类工作变快了/返工少了），
     写「本周最值得的调整」，带前后数据和证据。
  B. 如果没有，写「我发现的问题」，给 A/B/C 三个建议，
     把最重要的一个高亮，说明为什么选它。
- 最后一行只留一条证据链接或命令，让人能自己核对。
- 全文不超过 400 字。写长了没人看。

不要把原始 JSON 贴进周报；不要给评分或排名。
```

## 月报

月末那周用月报替代周报，不叠加。月报的提示词相同，把 `--days 7` 换成 `--days 30`，
并额外问一句：这个月的同类工作比上个月快了吗？估准率如何？
